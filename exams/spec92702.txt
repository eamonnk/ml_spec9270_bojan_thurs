Q1 (c) Data leakage can give over-optimistic model performance. Explain why and (4 marks)
discuss what is necessary to avoid data leakage.

Data leakage involves the use of test data in the training of the model. as such when a model tests is predictions on the test data it already
 knows the answer, thus providing over optimistic results, The result is an unrealistic estimate of generalisation accuracy. The model gains access to information it would not normally have when making predictions on unseen data, leading to over-optimistic performance results

Data leakage can also occur in preprocessing steps such as normalisation, imputation, or feature selection if test data is included when fitting these transformations. To avoid this, all preprocessing must be fitted on training data only and then applied to test data.

To avoid data leakage, the training and test datasets must remain completely separate. Any preprocessing steps such as scaling, encoding, imputation, or feature selection should be fitted only on the training data and then applied to the test data afterwards


Q1 (d) When decision tree pruning results in the removal of a sub-tree with the root of the sub-tree becoming a leaf node, what is the class label associated with this new leaf node? (4 marks)

When a subtree is pruned, its root becomes a leaf node labelled with the majority class of the training instances that reach that node. For example, if 70% of instances at that node belong to class "Yes", the leaf is labelled "Yes". Pruning is done to reduce overfitting — the removed subtree was making overly specific splits that fit training noise rather than genuine patterns, reducing generalisation ability

Q1 (i) Why is it not possible to use k-Means clustering with categorical data?

k-Means cannot be used with categorical data because the algorithm requires computing a centroid at each iteration — the mean of all instances assigned to a cluster. It is not possible to calculate a mean for categorical values (e.g. the mean of {Irish, French, Italian} is undefined). Without valid centroids, the algorithm cannot assign instances to clusters or iterate to convergence.

Q2 (a) You have been asked to build a classifier that will predict whether an indi vidual should qualify for a credit card or not. You have been provided with lists of individuals who have already applied for credit cards along with their outcome, whether they were awarded a credit card or not. You have been told that the key characteristics of the individual that are typically used to determine the outcome include Age, their employment status (i.e. employed or not), and whether they are a home owner or not. Describe how you will build a Naive Bayes classifier which can be used to predict the outcome. - (10 marks)

Q2(a) — Building a Naïve Bayes Classifier for Credit Card Qualification

Step 1 — Define the Problem

Target feature: Credit Card Outcome = {Approved, Denied}
Descriptive features: Age (continuous), Employment Status (Yes/No), Home Owner (Yes/No)
Binary classification problem — Naïve Bayes is an eager learner — model built once at training time
Naïve assumption: All descriptive features are conditionally independent given the class:


P(Employed=Yes AND HomeOwner=Yes | Approved) = P(Employed=Yes|Approved) × P(HomeOwner=Yes|Approved)


Step 2 — Preprocessing

Age is continuous — must be discretised into bins before applying NB as we cannot calculate P(Age=27.5|Approved) for every possible value
e.g. Age = {Young: <30, Middle: 30–50, Senior: >50}
Employment Status and Home Owner are already categorical — no transformation needed. NB works by counting occurrences directly — it does not calculate distances or multiply weights so numerical conversion is not required
Perform 80/20 train/test split — test data must never be used in training or preprocessing


Step 3 — Calculate Prior Probabilities from Training Data
The prior is the baseline probability of each class before seeing any features:

P(Approved) = number of approved applicants / total applicants
P(Denied) = number of denied applicants / total applicants

Example: if 600 of 1000 applicants were approved:

P(Approved) = 600/1000 = 0.6
P(Denied) = 400/1000 = 0.4


Step 4 — Calculate Likelihood Probabilities
For every feature value and every class, count occurrences in training data:

P(Employed=Yes | Approved) = count(Employed=Yes AND Approved) / count(Approved)
P(Employed=No | Approved) = count(Employed=No AND Approved) / count(Approved)
P(HomeOwner=Yes | Approved) = count(HomeOwner=Yes AND Approved) / count(Approved)
P(Age=Young | Approved) = count(Age=Young AND Approved) / count(Approved)
P(Age=Middle | Approved) = count(Age=Middle AND Approved) / count(Approved)
P(Age=Senior | Approved) = count(Age=Senior AND Approved) / count(Approved)

Repeat all of the above for the Denied class.
Note: All probabilities for a feature given a class must sum to 1:

P(Young|Approved) + P(Middle|Approved) + P(Senior|Approved) = 1.0


Step 5 — Apply Laplace Smoothing
Applied to all features as a standard safeguard — not just continuous ones. Prevents zero probability for any feature value not seen with a particular class in training:

P(feature=v | class) = (count + 1) / (total + number of possible values)

Without this, a single unseen combination multiplies the entire posterior to zero — destroying the prediction. For example:

P(HomeOwner=Yes | Denied) = 0 → entire P(Denied|query) = 0 — incorrect


Step 6 — Making a Prediction for a New Query
For a new applicant (e.g. Employed=Yes, HomeOwner=No, Age=Young) apply Bayes Theorem:

P(h|D) = P(D|h) × P(h) / P(D)

Expanding using the Naïve assumption — multiply likelihoods for each feature independently:

P(Approved|query) ∝ P(Approved) × P(Employed=Yes|Approved) × P(HomeOwner=No|Approved) × P(Age=Young|Approved)
P(Denied|query) ∝ P(Denied) × P(Employed=Yes|Denied) × P(HomeOwner=No|Denied) × P(Age=Young|Denied)

Note: P(D) — the evidence — is identical for both classes so can be ignored in the comparison. We only need the numerator.
Each new feature is new evidence that updates the probability — exactly like the medical diagnosis example where a positive test updates P(Disease), or the Monty Hall problem where the host opening a door updates P(prize location).

Step 7 — MAP Decision Rule
Apply the Maximum A Posteriori (MAP) decision rule — assign the query to the class with the highest posterior probability:

M_MAP(q) = argmax꜀ [ P(t=c) × Π P(qᵢ | t=c) ]

Where:

argmax꜀ = find the class c that maximises the expression
P(t=c) = prior probability of class c
Π P(qᵢ|t=c) = product of all feature likelihoods given class c

In plain terms:

If P(Approved|query) > P(Denied|query) → predict Approved
If P(Denied|query) > P(Approved|query) → predict Denied


Step 8 — Evaluate the Model

Run predictions on held-out test set (never seen during training)
Evaluate using confusion matrix, accuracy, precision and recall
Use k-fold cross validation for a more stable and accurate estimate of generalisation accuracy
Check for data leakage — ensure all preprocessing (binning, smoothing) was fitted on training data only

A complete 8 mark answer:

The confusion matrix summarises classifier performance by comparing actual vs predicted class labels across all instances in the test set. It produces four metrics:

TP: Correctly predicted positive
TN: Correctly predicted negative
FP: Predicted positive but actually negative (Type I error)
FN: Predicted negative but actually positive (Type II error)



Insights beyond misclassification rate:
1. Class specific errors: Misclassification rate is a single overall number — it does not reveal which classes are being confused. For example a model may classify all negative cases perfectly but fail completely on positive cases — the misclassification rate could still look acceptable
2. Class imbalance: If 95% of instances are class A and 5% are class B, a model that always predicts class A achieves 95% accuracy — but the confusion matrix immediately reveals it never correctly predicts class B
3. Different costs of errors: FP and FN have very different real world consequences:

Medical diagnosis: FN is catastrophic — missing a real disease is far worse than a false alarm
Spam filter: FP is costly — marking legitimate email as spam loses important messages
Misclassification rate treats both errors equally — confusion matrix separates them

4. Enables Precision and Recall calculation:

Precision = TP / (TP + FP) — of all predicted positive, how many were correct?
Recall = TP / (TP + FN) — of all actual positives, how many did we find?
Neither can be calculated from misclassification rate alone

(i) Most serious — Feature Selection
Including test data in feature selection means features are chosen based on their ability to predict both training AND test instances. This is direct data leakage into the model building process — the selected features are optimised for the test set giving a heavily inflated estimate of generalisation accuracy. In real deployment on truly unseen data the model will perform significantly worse.


(ii) Moderate — One-Hot-Encoder
If the encoder is fitted on all data including test set, it learns category values that may only appear in test data. This gives the model a slight advantage when predicting test instances. Less serious than feature selection as it does not directly involve the target variable — but still produces an overly optimistic accuracy estimate.


(iii) Least serious — Mean Imputation
Using the mean across both training and test data causes minimal leakage. The mean value of a feature changes very slightly when a small test set is included. The resulting inflation in accuracy is negligible compared to the other scenarios. Still technically incorrect and should be avoided — the imputer should always be fitted on training data only then applied separately to test data

Q2 (d) When compared with hold-out testing, cross validation testing can provide estimates of generalisation accuracy that are 
(i) more accurate and 
(ii) more stable. 
Explain both of these claims.

(8 marks)

Hold-out testing splits data into a fixed train and test set (e.g. 80/20). The model is trained once and tested once — fast but the result depends heavily on how the split falls. A lucky or unlucky split can give a misleadingly high or low accuracy estimate.
k-fold Cross Validation divides data into k equal folds (typically 5 or 10). The model is trained k times — each time using k-1 folds for training and 1 fold for testing. The final accuracy is the mean of all k accuracy scores.


(i) More Accurate:
In hold-out testing, some instances never appear in the test set at all. In k-fold cross validation, every instance is used for testing exactly once across the k iterations. This means the accuracy estimate is based on the full dataset — giving a more representative and accurate estimate of how the model will generalise to truly unseen data. It is not dependent on one particular lucky or unlucky split.


(ii) More Stable:
Hold-out produces a single accuracy value from one split — this has high variance and could vary significantly if the split was done differently. Cross validation produces k accuracy values which are averaged to give the final estimate. Averaging across k runs reduces variance — extreme results in any one fold are balanced out by the others. The resulting estimate is much more stable and consistent regardless of how the data happens to be divided.

ii. You have been asked to train a model on a text dataset that has high dimensionality and is sparse. Explain how you would reduce the dimensionality of the dataset and identify the best subset of features to use.


Why Text Data is High Dimensional and Sparse
Text data is inherently high dimensional because the Bag of Words representation creates one feature (column) for every unique word across the entire document corpus. A dataset with 10,000 unique words creates 10,000 features. It is sparse because any individual document only contains a small subset of those words — most feature values are zero. For example a document with 50 words in a 10,000 word vocabulary has 9,950 zero values.

Step 1 — TF-IDF Weighting (Text Specific Preprocessing)
Before feature selection, apply TF-IDF (Term Frequency — Inverse Document Frequency) weighting to reduce the impact of uninformative words:

TF-IDF(t, d) = TF(t,d) × IDF(t)
IDF(t) = log(|D| / |{d ∈ D : t ∈ d}|)

Where:

TF = how often term t appears in document d
IDF = log of total documents divided by documents containing term t

This penalises words that appear in almost every document (e.g. "the", "and") as they carry no discriminative power, and rewards words that appear frequently in some documents but rarely across the corpus — these are the most informative features.

Word appears in every document → IDF ≈ 0 → low TF-IDF → not useful
Word appears in a few documents → high IDF → high TF-IDF → informative


Step 2 — Filter Method (Reduce Dimensions)
Apply Information Gain (Mutual Information) as a filter to rank all remaining features by their individual predictive power for the target class:

IG(d, D) = H(D) − rem(d, D)


Score every word/token by how much it reduces entropy of the target variable
Rank all features by IG score
Keep the top k features — discard the rest
Fast and computationally efficient — important given the high dimensionality of text data
Does not depend on any specific classifier — can be applied before model selection

This significantly reduces the feature space from potentially tens of thousands of words down to the most informative subset.

Step 3 — Wrapper Method (Identify Best Subset)
Once the feature space is reduced by the filter, apply a Wrapper method to identify the optimal combination of features:

Sequential Forward Selection (SFS): Start with zero features, add one feature at a time — the feature that most improves model accuracy is added at each step
Sequential Backward Selection (SBS): Start with all remaining features, remove one at a time — the feature whose removal least reduces accuracy is dropped at each step

Wrappers evaluate feature combinations rather than individual features — they can detect when two features work better together than either does alone. Each subset is evaluated using cross-validation to avoid data leakage.

⚠️ Wrappers are computationally expensive — this is why the filter step is applied first to reduce the feature space before wrapping


Step 4 — Optional: PCA for Further Transformation
If dimensionality remains high after filter and wrapper selection, apply Principal Component Analysis (PCA):

Unsupervised projection method — no target variable needed
Projects data onto eigenvectors of the covariance matrix
Eigenvalues indicate the importance of each component — how much variance it captures
First principal component captures maximum variance; each subsequent component captures less
Retains the most informative structure of the data in far fewer dimensions


Note: PCA does not retain original features — it creates new composite dimensions. This reduces interpretability but maximises variance preservation.
